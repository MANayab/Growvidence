# Growvidence v0.2.0 — Release Draft

**Status:** Draft proposal. Do not tag or publish until the maintainer approves, PR #12 is merged, and final release verification is completed.

## Proposed tag
`v0.2.0`

## Proposed release title
`Growvidence v0.2.0 — Tracks and Tasks Foundation`

## Short description
An evidence-first learning tracker foundation: a public static site and local browser workspace for organizing learning tracks and tasks, with competency mastery intentionally kept separate from task completion.

## Highlights
- **Phase 0:** product principles, repository governance, architecture direction, draft data model, decisions and quality gates.
- **Phase 1:** public static Astro site, SEO/structured data, crawler assets, CI and GitHub Pages deployment.
- **Slice 1:** workspace shell, React island, hash navigation, theme preference and IndexedDB persistence foundation.
- **Slice 2 (PR #12, not merged yet):** tracks and task lifecycle, optional starter tracks, list/status board, accessible native “Move to…” controls, calendar views, validation, repositories and migration tests.

## What's new
- Create, rename, archive, soft-delete and permanently delete learning tracks.
- Add starter tracks only by explicit user action.
- Create/edit tasks with track, description, priority, local date-only due date, status, estimated/actual minutes and tags.
- Switch between list and status board; use labeled keyboard-operable native status controls.
- Browse All dates, daily, Monday-start weekly and monthly task due-date views.
- Local IndexedDB v3 persistence with Zod schemas and migration coverage.
- CI bundle budget is 200 KiB gzip for /app/ JavaScript.

## Known limitations
- Slice 2 is on Draft PR #12; it is not merged or deployed and must not be described as released until that changes.
- No journal, AI-use disclosure flow, competency/evidence/review engine, dashboard, JSON backup/restore, CSV export, accounts, backend, cloud sync, analytics, payments or PWA/offline experience.
- Browser IndexedDB is local storage, not encrypted storage or a backup; browser cleanup/device loss may remove data.
- Six suggested learning areas are user-added starter tracks, not approved competency rubrics.
- Competency-level definitions and rubrics remain subject to approval.
- The working product name has not been cleared for trademark/domain/app-store use.

## Proposed tagging convention
Use pre-1.0 Semantic Versioning:
- `0.MINOR.PATCH`: milestone increments for feature slices/milestone releases while API/data contracts are evolving; `PATCH` for backward-compatible fixes to a released milestone.
- Phase 0 governance/product foundation: propose `v0.1.0`.
- The proposed `v0.2.0` is a cumulative milestone containing Phase 0, Phase 1, Slice 1 and Slice 2 (once PR #12 is approved and merged). Phase 0 may be tagged `v0.1.0` as a prior milestone if the maintainer chooses to create that historical tag; `v0.2.0` is the current proposed milestone tag.
- Future feature milestones (e.g. journal, evidence, import/export) increment the minor number to `v0.3.0`, `v0.4.0`, etc.; patch-only fixes increment `v0.x.1`.
- Create annotated Git tags (`git tag -a v0.x.0 -m "Growvidence v0.x.0"`) pointing at the reviewed merge commit. Tags are immutable markers; never move or recreate published tags.
