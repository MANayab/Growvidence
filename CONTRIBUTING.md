# Contributing to Growvidence

Thank you for considering a contribution. Growvidence is in its foundation stage; the product and architecture are still being validated.

## Before contributing

- Read [README.md](README.md), [mind.md](mind.md), [AGENTS.md](AGENTS.md), and the relevant design documents.
- For a significant product or architecture change, open an issue or propose an ADR before implementation.
- Do not assume planned features are implemented.

## Workflow

1. Fetch the latest `main`.
2. Create a focused branch from that exact base.
3. Make a small, reviewable change.
4. Add or update tests for behavior changes.
5. Run the relevant checks and report exact results.
6. Update documentation and `brain.md` when decisions or project status change.
7. Open a pull request against `main`; do not merge it yourself.

Direct pushes to `main` are not part of the project workflow.

## Commit and PR expectations

- Use clear, imperative commit messages.
- Keep unrelated formatting or refactoring out of focused changes.
- Include context, scope, verification, screenshots where useful, and known limitations in PR descriptions.
- Never claim a check passed unless it actually ran and passed.

## Security

Never commit secrets or personal evidence. Report suspected vulnerabilities privately using the process in [SECURITY.md](SECURITY.md).

## Code of conduct

Participation is subject to [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
